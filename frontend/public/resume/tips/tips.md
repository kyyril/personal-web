Untuk membuat bullet point CV yang kuat, aku tidak menyarankan menggunakan STAR secara mentah untuk semua bagian resume.

**Resume bullet point punya tujuan berbeda dengan jawaban interview.** Resume harus membuat recruiter memahami tiga hal dalam beberapa detik:

1. Apa yang kamu kerjakan?
2. Seberapa kompleks atau penting pekerjaan tersebut?
3. Apa hasil atau bukti dampaknya?

Untuk target Software Engineer, Backend Engineer, Fintech, Big Tech, dan bahkan IT Business Analyst, aku merekomendasikan kombinasi framework berikut.

# **1. Framework terbaik berdasarkan bagian resume**

**Personal Projects**

Paling direkomendasikan: XYZ + Engineering Depth

Formula:

**Built X, measured by Y, by doing Z.**

Fokus:

- Apa yang dibangun?
- Masalah apa yang diselesaikan?
- Teknologi dan pendekatan teknis apa yang digunakan?
- Apa bukti kualitas atau hasilnya?

**Professional Experience**

Paling direkomendasikan: CAR + XYZ

Formula:

**Action + Scope + Method + Impact**

Fokus:

- Ownership dan tanggung jawab.
- Kompleksitas pekerjaan.
- Kontribusi individu.
- Dampak terhadap bisnis atau operasional.

**Undergraduate Thesis / Research**

Paling direkomendasikan: Research + Method + Findings

Formula:

**Research Objective + Methodology + Quantitative Findings**

Fokus:

- Masalah penelitian.
- Metodologi dan eksperimen.
- Parameter pengujian.
- Temuan kuantitatif.
- Validitas hasil.

**Open-Source Contributions**

Paling direkomendasikan: Contribution + Technical Impact

Formula:

**Contributed X to Y by implementing Z, resulting in W.**

Fokus:

- Repository atau proyek yang berkontribusi.
- Masalah yang diperbaiki.
- Perubahan kode atau dokumentasi.
- PR yang diterima atau di-merge.
- Dampak terhadap pengguna atau developer.

# **2. Framework yang perlu kamu ketahui**

Ada beberapa framework yang bisa dikombinasikan.

| Framework              | Formula                                   | Kegunaan                            |
| ---------------------- | ----------------------------------------- | ----------------------------------- |
| XYZ                    | Accomplished X, measured by Y, by doing Z | Impact-oriented bullets             |
| CAR                    | Challenge, Action, Result                 | Experience                          |
| PAR                    | Problem, Action, Result                   | Problem-solving                     |
| STAR                   | Situation, Task, Action, Result           | Mengembangkan cerita menjadi bullet |
| Google Resume Formula  | Action Verb + What + How + Result         | Resume engineering                  |
| Research Framework     | Objective + Method + Findings             | Thesis                              |
| Contribution Framework | Change + Implementation + Outcome         | Open source                         |
| Engineering Depth      | System + Technical Decision + Validation  | Technical projects                  |

Satu catatan: XYZ merupakan formula yang populer dalam panduan resume Google. Sementara Research Framework, Contribution Framework, dan Engineering Depth di atas merupakan pola penulisan yang disesuaikan dengan kebutuhan masing-masing bagian, bukan standar resmi dengan nama baku.

## **B. Personal Projects**

Personal project tidak harus dipaksakan memiliki business impact.

Recruiter ingin mengetahui apakah kamu mampu membangun sesuatu secara mandiri dan memahami keputusan engineering di baliknya.

**Framework yang paling cocok:**

`Built + System Capability + Technical Implementation + Validation`

Jangan hanya menulis:

- Developed a REST API using Go.
- Used PostgreSQL and Redis.
- Implemented authentication.

Itu hanya menjelaskan aktivitas, bukan menunjukkan kemampuan engineering.

## **C. Undergraduate Thesis / Research**

Untuk skripsi, gunakan framework penelitian, bukan business impact formula.

**Kenapa framework ini kuat?**

| Komponen    | Bukti penelitian                |
| ----------- | ------------------------------- |
| Objective   | Scalability and reliability     |
| Method      | Event-driven microservices      |
| Tools       | Go, RabbitMQ, k6                |
| Experiment  | 200 VUs                         |
| Finding     | P95 latency turun 58.9%         |
| Reliability | Zero event loss dalam pengujian |

Thesis kamu punya keunggulan karena memiliki angka eksperimen yang bisa dipertanggungjawabkan. Jangan sampai angka tersebut hilang hanya karena ingin membuat bullet lebih singkat.

## **D. Open-Source Contributions**

Untuk open source, gunakan framework yang menunjukkan kontribusi terhadap codebase milik orang lain.

**Hindari:**

- Contributed to Google open source.
- Helped improve OpenTelemetry.
- Participated in open-source communities.

Kalimat tersebut terlalu generik. Sebutkan repository, PR, dan perubahan yang benar-benar kamu buat.

Untuk open source, satu PR yang benar-benar di-merge dan menjelaskan perubahan teknisnya bisa lebih kuat daripada lima klaim kontribusi yang tidak jelas.

# **5. Berapa bullet point yang ideal?**

Untuk resume fresh graduate dengan pengalaman teknis seperti milikmu:

| Section                 | Jumlah bullet                   |
| ----------------------- | ------------------------------- |
| Professional Experience | 3–5 per role                    |
| Personal Projects       | 2–3 per project                 |
| Undergraduate Thesis    | 2–4                             |
| Open Source             | 1–2 per meaningful contribution |

Tidak harus semua project dimasukkan. Pilih yang paling relevan dengan pekerjaan yang dilamar.

# **6. Aturan penting agar bullet point terlihat seperti resume Big Tech**

Ada beberapa kesalahan yang perlu kamu hindari.

| Hindari                               | Lebih baik                                                  |
| ------------------------------------- | ----------------------------------------------------------- |
| Responsible for developing...         | Developed...                                                |
| Worked on backend services...         | Implemented...                                              |
| Helped the team build...              | Built / Contributed to...                                   |
| Used Go and RabbitMQ...               | Implemented asynchronous messaging using Go and RabbitMQ... |
| Improved performance significantly... | Reduced P95 latency by 58.9%...                             |
| Successfully completed the project... | Jelaskan hasil konkret proyek                               |

Ada juga lima aturan yang aku sarankan:

1. **One bullet, one major accomplishment.** Jangan memasukkan lima aktivitas berbeda dalam satu kalimat.
2. **Prioritize evidence over adjectives.** Angka dan hasil lebih kuat daripada kata *scalable, robust, innovative* tanpa bukti.
3. **Use strong action verbs.** Built, Designed, Implemented, Automated, Optimized, Evaluated, Reduced.
4. **Avoid technology dumping.** Jangan memasukkan semua teknologi hanya demi ATS.
5. **Never fabricate impact.** Bedakan hasil pengujian, hasil implementasi, dan dampak penggunaan nyata.

# **7. Rekomendasi final untuk standar resume kamu**

Kalau aku menyusun resume kamu dengan target perusahaan teknologi, fintech, dan perusahaan besar, aku akan menggunakan standar ini:

| Section              | Framework utama         | Fokus                |
| -------------------- | ----------------------- | -------------------- |
| Experience           | CAR + XYZ               | Ownership & impact   |
| Personal Projects    | Engineering Depth       | Technical capability |
| Undergraduate Thesis | Research + Findings     | Analytical ability   |
| Open Source          | Contribution + Evidence | External validation  |

**Satu strategi tambahan:** jangan menggunakan satu versi bullet point untuk semua lowongan.

Misalnya:

- Backend Engineer: tonjolkan Go, distributed systems, database, reliability.
- Software Engineer: tonjolkan ownership, software delivery, testing, dan problem-solving.
- IT Business Analyst: tonjolkan requirements, stakeholder communication, dan process improvement.
- Solution Architect: tonjolkan architecture decisions, integration, trade-offs, dan system constraints.
- Fintech: tonjolkan payment integration, transaction consistency, idempotency, dan reliability jika memang pernah dikerjakan.

Dengan begitu, kamu tidak perlu mengganti pengalamanmu. Kamu hanya mengubah penekanan berdasarkan kebutuhan posisi.

**Kesimpulan:** Gunakan XYZ sebagai fondasi, tetapi jangan memaksakan semua bullet harus memiliki angka. Bullet tanpa metrik masih bisa kuat jika menunjukkan kompleksitas teknis, keputusan engineering, ownership, atau kontribusi yang jelas.

tips dari claude terkait resume di era sekarang:
Cuma main keyword sekarang nggak cukup, dan kalau berlebihan bisa merugikan. Tapi "canggih" itu relatif, karena tergantung perusahaannya.

**Di balik layar**

Di banyak perusahaan sekarang ada dua lapisan. Lapisan pertama adalah ATS klasik berbasis keyword dan aturan, yang masih jadi tulang punggung. Lapisan kedua adalah AI/LLM yang merangkum dan meranking kandidat, tapi sebagian besar screening sebenarnya masih keyword dan rules. Alurnya kira-kira: parsing, matching dengan job description, lalu ranking. Hanya top N yang dikirim ke recruiter. Untuk matching, sistem modern mengubah resume dan job description jadi vector embeddings, jadi yang dicocokkan itu makna, bukan kata persisnya.

**Poin-poin pentingnya**

1. **Parsing adalah gerbang pertama.** Kalau teks resume nggak bisa dibaca mesin, AI nggak bisa menilai isinya. Penyebab umumnya tabel, kolom, dan teks dalam bentuk gambar. Jadi, pakai satu kolom, judul section standar (Pengalaman, Pendidikan, Skill), dan file yang teksnya bisa diseleksi.

2. **Makna lebih penting daripada kata persis.** AI paham bahwa "P&L ownership" dan "managed budget" itu berkaitan, jadi nggak perlu menjejalkan frasa yang sama berulang-ulang. Pakai bahasa dari lowongan secara natural untuk skill yang memang kamu punya.

3. **Bukti lebih berharga daripada daftar skill.** Sistem semantik memberi nilai pada bukti kemampuan, bukan pengulangan kata. Tulis hasil konkret (angka, skala, dampak), bukan cuma "menguasai Excel".

4. **Keyword tetap dipakai untuk syarat wajib.** Banyak tools menggabungkan semantic ranking dengan keyword matching untuk filter kepatuhan seperti izin kerja atau lisensi. Syarat hard seperti sertifikasi, lokasi, atau jenjang pendidikan sebaiknya tertulis jelas.

5. **Trik curang berisiko.** Keyword stuffing dan teks tersembunyi sekarang di-flag, bukan diberi poin. Prompt injection juga terdeteksi dan dipenalti. Jangan coba-coba teks putih atau instruksi tersembunyi untuk AI.

6. **"Auto-reject" sebagian besar mitos.** Yang lebih sering terjadi: resume masuk antrean berperingkat sampai recruiter membuka lowongan dan mencari. Posisi kamu di ranking menentukan apakah kamu keburu dilihat. Manusia tetap pengambil keputusan akhir, karena AI cuma menyaring dan merangkum.

7. **Resume hasil AI yang generik gampang ketahuan.** Kandidat makin sering pakai AI untuk menulis resume, dan banyak hiring manager sudah bisa mengenali yang template-an. AI boleh membantu merapikan, tapi isinya harus pengalaman nyata kamu.

**Catatan penting**

- Banyak sumber soal ini berasal dari blog vendor tools resume atau ATS, jadi angka seperti "akurasi 92%" atau "target match 65-80%" jangan dianggap pasti.
- Adopsinya belum merata. Menurut SHRM 2026, di tim recruiting yang memakai AI, 44% menggunakannya untuk screening resume. Jadi sebagian perusahaan masih pakai filter sederhana, dan sebagian lagi sudah pakai semantic ranking.

**Strategi praktisnya**

Sesuaikan resume untuk tiap lowongan: baca JD, tonjolkan pengalaman yang relevan memakai istilah yang mereka pakai (selama jujur), taruh pencapaian terukur, dan jaga format tetap sederhana. Resume yang enak dibaca recruiter dalam beberapa detik biasanya juga ramah mesin.

Untuk mahasiswa CS yang cari magang, bobot penilaiannya beda dari kandidat senior. Recruiter magang tahu kamu masih mahasiswa dengan pengalaman kerja terbatas, jadi yang mereka cari adalah **bukti kemampuan dan potensi belajar**. Skill relevan dan proyek/portfolio masuk prioritas tertinggi, dan magang formal hanyalah salah satu cara membuktikan kemampuan.

"Terlihat top 0.5%" paling aman dicapai dengan **benar-benar punya sinyal kuat**, bukan dengan memoles klaim. Klaim yang dibesar-besarkan mudah ketahuan di technical interview. Berikut yang bisa kamu bangun dan tonjolkan.

## 1. Struktur resume junior CS

- **Panjang:** satu halaman, dengan Education di dekat bagian atas.
- **Urutan:** Header (email, LinkedIn, GitHub, portfolio) → Education → Projects → Experience (kalau ada) → Skills → Leadership/Achievements.
- **Education:** kampus, jurusan, perkiraan lulus, IPK (kalau bagus, kira-kira ≥3.5), dan 4-6 mata kuliah relevan seperti Struktur Data, Algoritma, Basis Data, Jaringan, Sistem Operasi, dan ML. Contoh resume di panduan magang CS memang mencantumkan Relevant Coursework dan Dean's List.
- **Ringkasan:** boleh dilewati. Kalau dipakai, 2 baris saja dan spesifik, misalnya *"Mahasiswa CS semester 5, fokus backend (Go, PostgreSQL), membangun dan men-deploy 3 aplikasi dengan pengguna nyata."*
- **Skills:** kelompokkan (Languages, Frameworks, Tools, Database). Cantumkan hanya yang bisa kamu bahas di interview. Skill yang tidak relevan termasuk kesalahan umum mahasiswa CS. Hindari "team player" atau "hard worker" di daftar skill.

## 2. Projects adalah senjata utamamu

Satu proyek yang matang lebih berharga daripada 8 proyek tutorial. Tingkatannya:

| Level | Ciri proyek |
|---|---|
| Biasa | Clone dari tutorial (to-do app, kalkulator, e-commerce template) |
| Bagus | Ide sendiri, ada database, auth, dan kode rapi di GitHub dengan README jelas |
| Top | **Di-deploy dan bisa diakses**, ada pengguna nyata (walau 20-50 orang), ada tes, CI sederhana, dokumentasi, dan alasan desain yang bisa kamu jelaskan |

Rumus bullet: kata kerja aksi + teknologi + apa yang dibangun atau diperbaiki + hasil terukur. Contoh:

- *"Membangun REST API (Go, PostgreSQL, Redis) untuk aplikasi pemesanan kampus; caching menurunkan latency rata-rata dari 480ms ke 90ms pada 1.000 request uji."*
- *"Dipakai 120 mahasiswa aktif di fakultas; mengumpulkan feedback via form dan merilis 6 perbaikan dalam 2 bulan."*

Ide proyek yang menonjol:
- Selesaikan masalah nyata di sekitarmu (kampus, UMKM, organisasi), karena itu otomatis punya "pengguna" dan cerita.
- Hindari proyek yang terlalu mirip dengan ribuan resume lain, seperti prediksi Titanic atau clone Netflix tanpa sentuhan sendiri.
- Kalau fokus AI/ML, tunjukkan evaluasi, error analysis, dan deployment, bukan cuma akurasi notebook.

## 3. Sinyal tambahan yang membedakan

- **Kompetisi:** hackathon, organisasi, dan kepemimpinan ikut dinilai recruiter magang karena menunjukkan kerja sama, komunikasi, dan inisiatif. Contohnya hackathon, Gemastik, ICPC, atau Kaggle. Peringkat atau hasil konkret jauh lebih kuat daripada sekadar ikut.
- **Open source:** satu atau dua PR yang di-merge ke proyek nyata, walau kecil (perbaikan bug atau dokumentasi).
- **Pengalaman non-formal:** freelance, proyek untuk dosen atau lab, asisten dosen/praktikum, dan mentoring juga dihitung. Tulis dengan format hasil yang sama seperti pengalaman kerja.
- **Kepemimpinan:** ketua divisi, pengurus komunitas, atau penyelenggara acara. Sebutkan skala dan hasilnya (misalnya "120 peserta, 5 sponsor").
- **Sertifikasi:** pilih yang relevan dan terpercaya (cloud, misalnya). Tapi jangan menumpuk sertifikat kursus ringan, karena nilainya jauh di bawah proyek nyata.
