### Shortlink: Production URL Shortener API
* **Tech Stack:** Go, PostgreSQL, sqlc, Prometheus, Docker, Railway.
* **Di Resume:**
  * *"Architected sub-millisecond redirects in Go; batched click telemetry via PostgreSQL binary COPY FROM."*
  * *"Guaranteed zero duplicate writes via SHA-256 idempotency; enforced IP rate limiting and keyset pagination."*
* **Respon Lisan Profesional (High-Throughput Ingestion & Idempotensi):**
  > *"Proyek Shortlink dirancang sebagai layanan API penyingkat URL skala produksi berkinerja tinggi menggunakan Go dan PostgreSQL, dengan fokus rekayasa pada penyelesaian dua tantangan utama sistem backend: latensi pengalihan (redirect latency) dan kapasitas penyerapan data telemetri (telemetry ingestion).*
  > 
  > *Tantangan pertama terkait Latensi Pengalihan dan Pengumpulan Analitik:*
  > *Pada sistem konvensional, setiap aktivitas klik pada tautan pendek umumnya langsung melakukan operasi penulisan (INSERT) ke basis data, yang dapat mengakibatkan penurunan kecepatan respon redirect saat terjadi lonjakan traffic. Pada arsitektur yang saya kembangkan, saya mempertahankan latensi redirect pada kisaran sub-millisecond dengan memisahkan proses pencatatan telemetri secara asinkron menggunakan non-blocking buffered channel di Go. Data klik diagregasi sementara di memori, kemudian dialirkan ke PostgreSQL secara berkala menggunakan protokol biner COPY FROM dalam skema batch. Pola ini meminimalisasi beban koneksi basis data dan meningkatkan throughput penulisan secara signifikan.*
  > 
  > *Tantangan kedua terkait Idempotensi dan Efisiensi Kueri Data:*
  > *Untuk mencegah penulisan data duplikat akibat pengiriman ulang request jaringan secara bersamaan (concurrent race conditions), saya mengimplementasikan mesin idempotensi berbasis hash SHA-256 dari tautan sumber. Dengan demikian, keunikan data dijamin secara deterministik.*
  > *Selain itu, untuk layanan penelusuran riwayat tautan, saya menghindari metode OFFSET pagination konvensional yang memiliki kompleksitas waktu tinggi pada volume data besar. Sebagai gantinya, saya menerapkan Keyset (Cursor) Pagination guna memastikan waktu respon kueri tetap konstan pada tingkat sub-millisecond, yang dipadukan dengan kebijakan IP rate limiting berbasis token-bucket guna melindungi ketersediaan layanan dari potensi penyalahgunaan atau serangan DoS."*
